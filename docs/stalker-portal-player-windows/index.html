Stalker workflow

A Windows-focused way to test your legal Stalker Portal source

Stalker Portal support is not the same as opening a basic playlist. Some portals require a specific URL structure, request user agent, device-style fields, profile values, or other compatibility details. BLAZIN is built to give Windows users a controlled place to test those details while still keeping the daily viewing workflow easy to navigate.

When the source returns compatible data, BLAZIN organizes it into the player features users expect: Live TV, Movies, Series, categories, EPG, channel logos, posters, search, favorites, and playback choice. When something is missing, BLAZIN does not fake it—the data must come from the source.

  • Use a dedicated Stalker Portal profile path.
  • Set request user agent values when your legal source requires them.
  • Use advanced Stalker/STB fields for compatibility testing.
  • Browse categories, guide data, artwork, favorites, and playback options when available.

Troubleshooting

Common Stalker Portal checks

  • Verify the portal URL and path exactly match what your source requires.
  • Confirm the profile is using the correct login type, not a plain M3U workflow.
  • Check whether a custom user agent is required.
  • Review advanced field values such as STB type, version, device identifiers, or related profile data only when required.
  • If one section is missing, the portal may not return that section or may use a different endpoint behavior.
